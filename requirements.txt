# fastembed is pinned exactly, and not to "whatever is current". It supplies the
# BM25 half of every hybrid query, and `store.py restore` re-derives sparse
# vectors from payload text rather than shipping them -- which is only equivalent
# to shipping them while the BM25 hyperparameters match the machine that built
# the export. check_bm25_params() compares them against the manifest and refuses
# to run on drift. The current export
# (data/qdrant/qdrant_export/collection_config.json) records:
#     bm25_params: k=1.2, b=0.75, avg_len=256.0, english, stemmer on,
#                  fastembed 0.8.1
# so this pin is read off the build machine, not chosen. Change it only together
# with a rebuild, or hybrid search gets quietly worse than what was evaluated.
